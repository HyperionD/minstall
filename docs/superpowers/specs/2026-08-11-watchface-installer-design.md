# 小米手环 10 Pro 表盘直装工具 —— 设计文档

日期：2026-08-11
状态：已确认

## 1. 背景与目标

开发一个跨平台 GUI 工具，通过 BLE 直连小米手环 10 Pro，将 `.bin` 表盘文件直接安装到手环（不经过官方 App）。

**目标用户**：手环 10 Pro 用户，已自行通过第三方工具获取 authkey，手头有 `.bin` 表盘文件。

**明确不做（YAGNI）**：
- 不做表盘预览（不解析 bin 内部格式渲染）
- 不做设备上已装表盘的管理/删除
- 不做表盘商店/下载
- 不做 authkey 提取（用户自行获取）
- 不做多设备同时连接（单设备会话）

## 2. 技术路线

- **整体方案**：POC 验证先行 → Tauri 正式开发
- **阶段 1（POC）**：Python + bleak 最小验证脚本，用最便宜的方式验证最大风险（协议兼容性）
- **阶段 2（正式应用）**：Tauri 2.x（Rust 后端 + Web 前端）
  - Rust 侧：`btleplug` 跨平台 BLE
  - 前端：React + TypeScript，轻量

**关键风险**：Band 10 Pro 是否兼容社区已有的 Band 9（Furhat 族）BLE 协议。方案设计优先消解此风险。

## 4. 阶段 1 —— POC 验证

### 目标

用最小成本回答三个问题：

1. **设备可达性**：`scan.py` 能否发现 10 Pro、枚举出的 GATT service/characteristic UUID 是否与 Band 9 已知协议（Furhat 族）匹配
2. **认证可行**：`auth.py` 用用户提供的 authkey 能否完成认证握手（确认 authkey 长度/格式/流程与 Band 9 是否一致）
3. **推送可行**：`install.py` 能否把一个测试 `.bin` 表盘推送到手环并出现在表盘列表中

### 验收标准（全部满足才进入阶段 2）

- [ ] UUID 与 Band 9 参考实现匹配（或差异可解释）
- [ ] 认证握手成功
- [ ] 推送完成，手环实际显示新表盘
- [ ] 记录协议差异笔记 → 写入 `docs/protocol-notes.md`

### 使用注意

使用工具时需断开手机与手环的连接（BLE 连接独占）。此提示在 POC 与正式应用界面中均需体现。

## 5. 阶段 2 —— Tauri 应用架构

### Rust 后端模块划分（单一职责，便于独立测试）

```
src-tauri/src/
├── main.rs              # 应用入口
├── commands.rs          # Tauri command 桥接层（薄，无业务逻辑）
├── ble/
│   ├── mod.rs
│   ├── scanner.rs       # BLE 扫描/设备发现
│   ├── connection.rs    # 连接管理、GATT 服务/特征句柄缓存
│   └── errors.rs        # BLE 错误类型映射
├── protocol/
│   ├── mod.rs
│   ├── auth.rs          # authkey 认证握手
│   ├── watchface.rs     # bin 文件读取、表盘推送（分块 + 应答 + 进度回调）
│   └── consts.rs        # UUID、分块大小、超时等协议常量（来自 POC 笔记）
└── events.rs            # 进度/状态事件 → 前端
```

### Tauri Commands（前后端接口）

| Command | 输入 | 输出/事件 |
|---|---|---|
| `scan_devices` | — | 设备列表（名称/地址/信号强度） |
| `connect` | 地址 | 连接结果 |
| `authenticate` | authkey（hex 字符串或文件路径） | 认证结果 |
| `install_watchface` | bin 文件路径 | 进度事件 `install:progress` → 完成/失败 |
| `disconnect` | — | — |

### 界面流程（三屏轻量向导）

1. **连接页**：扫描并选择手环 + 输入/加载 authkey + 醒目提示「请先断开手机与手环的连接（BLE 独占）」
2. **安装页**：选择 `.bin` 文件 → 显示文件信息 → 点击安装 → 实时进度条 + 日志区（打印协议交互过程，方便排查）
3. **结果页**：成功/失败 + 错误详情 + 重试入口

## 6. 错误处理

| 场景 | 处理方式 |
|---|---|
| 蓝牙不可用 / 无权限 | 引导页检测 + 明确错误提示（附平台开启方法） |
| 扫描超时 / 找不到设备 | 可重试，提示确认手环处于可发现状态 |
| 连接失败 / 连接中断 | 重试；推送中断时前端保留进度，支持重连后续传 |
| 认证失败 | 明确提示「authkey 无效」，不猜测其他原因 |
| bin 文件不存在 / 不可读 | 安装前校验文件存在性与大小 |
| 推送中途失败 | 日志区输出失败帧的上下文（当前分块序号），便于与协议笔记对照排查 |

## 7. 测试策略

### 阶段 1（POC）

- 验证脚本本身即测试：`scan.py` / `auth.py` / `install.py` 三步递进，每步输出结构化结果（JSON）
- 验证时记录：设备固件版本、GATT 服务列表、协议差异 → 写入 `docs/protocol-notes.md`

### 阶段 2（Tauri 应用）

- **单元测试**（Rust）：
  - `watchface.rs` 的分块逻辑（输入 bin → 输出协议帧序列，模拟应答）
  - auth 握手状态机（mock 应答数据）
  - 协议常量与 POC 笔记一致性（断言 consts.rs 关键值）
- **集成验证**（真机，手动清单）：
  1. 冷启动扫描 → 发现设备
  2. 输入正确 authkey → 认证成功
  3. 安装合法 bin → 手环出现新表盘
  4. 输入错误 authkey → 明确失败提示
  5. 安装损坏文件 → 前置校验拦截
  6. 推送中途断开蓝牙 → 错误提示 + 可重试
- **平台覆盖**：开发主平台 + 至少一个其他平台手动过一遍流程（视可用环境而定）

## 8. 协议不确定性兜底

- 若 POC 发现 10 Pro 协议与 Band 9 有差异，`consts.rs` 集中管理所有协议常量，适配只改一处
- 推送协议无法打通时，POC 阶段的日志/笔记作为排查依据，回头决定是否需要抓包逆向（超出当前范围）
